# Отчёт по индивидуальному заданию 1

**Вариант 27 — однопутный железнодорожный участок**

Выполнила: Харитонова Лилия Геннадиевна  
Группа: БПИ253

## 1. Постановка задачи

Две станции соединены одним железнодорожным путём. С обеих сторон к участку
прибывают пассажирские и грузовые поезда. У каждого поезда есть номер,
направление движения, тип и время прибытия.

На участке нельзя одновременно пропускать поезда встречных направлений. В
простом режиме на пути может находиться только один поезд. В групповом режиме
можно пропустить несколько поездов одного направления, если не превышена
вместимость и соблюдается безопасный интервал между въездами.

Диспетчер выбирает направление и выдаёт разрешение на въезд. Пассажирские
поезда могут иметь приоритет, но остальные поезда не должны ждать бесконечно.
Программа должна завершаться как после прохождения всех поездов, так и после
прерывания пользователем.

## 2. Входные параметры

Параметры передаются через командную строку.

| Параметр | Назначение |
| --- | --- |
| `--left N`, `--right N` | количество поездов каждого направления |
| `--passenger-percent N` | вероятность пассажирского поезда от 0 до 100 |
| `--arrival-min N`, `--arrival-max N` | диапазон модельного времени прибытия |
| `--travel N` | время прохождения участка |
| `--capacity N` | вместимость участка |
| `--gap N` | минимальный интервал между въездами |
| `--max-group N` | максимальный размер группы одного направления |
| `--strategy fifo` | выбор по времени прибытия |
| `--strategy priority` | приоритет пассажирских поездов |
| `--max-wait N` | порог ожидания, после которого выбирается старый поезд |
| `--seed N` | начальное значение генератора случайных чисел |
| `--delay-ms N` | задержка между шагами для наглядности |
| `--until N` | остановка на указанной модельной минуте |
| `--log PATH` | имя файла подробного лога |

Если параметры не указаны, используются значения по умолчанию. Функция
`read_config` читает аргументы и проверяет, что числа находятся в допустимых
границах.

## 3. Структура проекта

Программа написана на языке C и разделена на несколько небольших файлов.

| Файл | Назначение |
| --- | --- |
| `main.c` | запуск программы, открытие лога и обработка `Ctrl+C` |
| `config.c` | значения по умолчанию и чтение параметров |
| `simulation.c` | создание поездов и основной цикл моделирования |
| `railway.h` | структуры, перечисления и объявления функций |
| `tests.c` | тесты основных функций и режимов |
| `run_tests.sh` | запуск тестов |
| `run_examples.sh` | запуск подготовленных примеров |
| `Makefile` | команды сборки |

Программа работает в одном процессе и одном потоке. Поезда хранятся в массиве,
а их действия по очереди обрабатываются внутри общего цикла.

## 4. Основные структуры данных

Структура `Train` хранит номер поезда, направление, тип, время прибытия, время
въезда, время выезда и текущее состояние.

Состояния поезда заданы `TrainState`:

- `PLANNED` — поезд ещё не прибыл;
- `WAITING` — поезд прибыл и ждёт разрешения;
- `ON_TRACK` — поезд находится на участке;
- `FINISHED` — поезд закончил движение.

Структура `Config` хранит все настройки запуска. `Direction`
задаёт свободный участок и два направления движения. `RunResult`
задаёт причину завершения программы.

### 4.1. Отображение сущностей и их взаимодействия

В первой части задания поезда не создаются как отдельные процессы или потоки.
Вся модель выполняется в одном процессе и одном потоке.

| Сущность | Представление в программе | Поведение |
| --- | --- | --- |
| поезд | элемент массива `Train` | прибывает, ждёт, въезжает и заканчивает путь путём смены состояния |
| станции | направления `LEFT` и `RIGHT` | с каждой стороны ожидают поезда своего направления |
| однопутный участок | переменные `direction` и `occupied` | хранит направление движения и число поездов на пути |
| диспетчер | функции `choose_direction` и `choose_train` | выбирает направление и поезд для въезда |
| модельное время | переменная `minute` | увеличивается после каждого прохода цикла |

Пример сценария взаимодействия:

1. Два поезда прибывают с разных сторон и переходят из состояния `PLANNED` в
   состояние `WAITING`.
2. Диспетчер сравнивает ожидающие поезда и выбирает направление движения.
3. Выбранный поезд получает разрешение и переходит в состояние `ON_TRACK`.
4. Поезд встречного направления остаётся в очереди, пока участок занят.
5. Через заданное время первый поезд освобождает участок и получает состояние
   `FINISHED`.
6. После освобождения участка диспетчер может выбрать другое направление.

Таким образом, взаимодействие сущностей моделируется последовательным
изменением их состояний в общем цикле.

## 5. Алгоритм работы

Один проход основного цикла соответствует одной модельной минуте. На каждом
шаге выполняются следующие действия:

1. Проверяется запрос на завершение через Ctrl+C.
2. С участка выходят поезда, закончившие движение.
3. Если участок освободился, текущее направление сбрасывается.
4. Новые поезда переходят из состояния PLANNED в WAITING.
5. Диспетчер выбирает направление движения.
6. При наличии места и соблюдении интервала выбранный поезд получает разрешение
   и въезжает на участок.
7. Функция `valid_state` проверяет основные правила.
8. Если все поезда завершили путь, цикл заканчивается.

Тип и время прибытия поездов выбираются с помощью `rand`. Параметр seed
позволяет повторить запуск с теми же исходными данными на одной системе.

## 6. Работа диспетчера

Функция `oldest` ищет поезд, который дольше всех ждёт в выбранном направлении.
Если несколько поездов прибыли одновременно, выбирается поезд с меньшим
номером.

При стратегии FIFO диспетчер выбирает самый старый поезд. При стратегии
priority сначала рассматриваются пассажирские поезда. Перед этим проверяется
время ожидания самого старого поезда. Если оно достигло `max-wait`, старый поезд
получает приоритет независимо от типа.

Направление нельзя менять, пока на участке находятся поезда. Ограничение
`max-group` не позволяет бесконечно пропускать поезда только с одной стороны.

## 7. Проверка правил

После каждого шага вызывается функция `valid_state`. Она проверяет:

- число поездов на участке;
- соответствие вместимости;
- одинаковое направление всех поездов на участке;
- правильность времени въезда и выезда;
- соответствие сохранённого количества фактическому состоянию массива.

Если правило нарушено, создаётся событие INVARIANT, и программа завершается с
кодом ошибки.

## 8. Пользовательский интерфейс и логирование

Пользователь управляет программой через параметры командной строки. Команда
`./railway --help` выводит справку. При неизвестном параметре, пропущенном
значении или недопустимом числе программа сообщает об ошибке.

В терминал выводятся основные события: запуск, прибытие, разрешение диспетчера,
въезд, выезд, предупреждения и итоговая статистика. Полный лог также содержит
постановку в очередь, выбор направления, прохождение участка и его
освобождение.

Пример строки:

```text
time=00005 event=ENTER train=003 dir=L-R occupancy=2 | Поезд въехал на участок
```

- `time` — текущая модельная минута;
- `event` — тип события;
- `train` — номер поезда;
- `dir` — направление;
- `occupancy` — число поездов на участке.

Значение `time` не является настоящим временем работы программы. Параметр
`--delay-ms` только замедляет вывод, чтобы за событиями было удобнее наблюдать.
После итоговой строки программа сообщает имя файла полного лога:

```text
Подробный лог записан в файл: railway.log
```

## 9. Завершение программы

При обычной работе программа заканчивается после прохождения всех поездов.
Параметр `--until` позволяет остановить моделирование на определённой минуте.

Для обработки Ctrl+C используется сигнал SIGINT. Обработчик не завершает
программу сразу, а устанавливает флаг stop_requested. Основной цикл замечает
флаг, записывает частичную статистику и корректно заканчивает работу.

## 10. Сборка и запуск

Сборка программы:

```bash
make
```

Запуск с параметрами по умолчанию:

```bash
./railway
```

Пример простого режима:

```bash
./railway --left 3 --right 3 --capacity 1 --strategy fifo
```

Пример группового режима:

```bash
./railway --left 5 --right 4 --capacity 3 --gap 1 --max-group 3 --strategy priority
```

В зависимости от исходных данных программа может завершиться следующими
способами:

| Исходные данные или действие | Результат |
| --- | --- |
| корректные параметры | все поезда проходят участок, код 0 |
| `--until N` | остановка на минуте `N` и частичная статистика, код 2 |
| нажатие `Ctrl+C` | корректная остановка и частичная статистика, код 4 |
| неверный параметр | сообщение об ошибке до начала моделирования, код 1 |

## 12. Ограничения

Модель использует дискретное время и хранит не более 200 поездов. Длина и
скорость поездов отдельно не моделируются. Безопасный интервал задаётся между
моментами въезда. Параметр `passenger-percent` задаёт вероятность типа каждого
поезда, поэтому фактическая доля пассажирских поездов может отличаться от
указанного значения.

## 13. Итог

В программе реализовано последовательное моделирование однопутного участка,
простой и групповой режимы, две стратегии диспетчера, ограничение ожидания,
логирование, проверка правил и корректное завершение. Работа программы
проверена тестами и запусками с разными исходными данными.
