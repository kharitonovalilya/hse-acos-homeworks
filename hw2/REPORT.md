# Отчёт по индивидуальному заданию 2

**Вариант 27 — однопутный железнодорожный участок**

Выполнила: Харитонова Лилия Геннадиевна  
Группа: БПИ253

## 1. Постановка задачи

Две станции соединены одним железнодорожным путём. С обеих сторон к участку
прибывают пассажирские и грузовые поезда. У каждого поезда есть номер,
направление движения, тип и время прибытия.

На участке нельзя одновременно пропускать поезда встречных направлений. В
простом режиме на пути может находиться только один поезд. В групповом режиме
можно пропустить несколько поездов одного направления, если не превышена
вместимость и соблюдается безопасный интервал между въездами.

Диспетчер выбирает направление и выдаёт разрешение на въезд. Пассажирские
поезда могут иметь приоритет, но остальные поезда не должны ждать бесконечно.
Диспетчер и каждый поезд работают в отдельных потоках. Программа должна
завершаться после прохождения всех поездов и при прерывании пользователем.

## 2. Входные параметры

Параметры передаются через командную строку.

| Параметр | Назначение |
| --- | --- |
| `--left N`, `--right N` | количество поездов каждого направления |
| `--passenger-percent N` | вероятность пассажирского поезда от 0 до 100 |
| `--arrival-min N`, `--arrival-max N` | диапазон модельного времени прибытия |
| `--travel N` | время прохождения участка |
| `--capacity N` | вместимость участка |
| `--gap N` | минимальный интервал между въездами |
| `--max-group N` | максимальный размер группы одного направления |
| `--strategy fifo` | выбор по времени прибытия |
| `--strategy priority` | приоритет пассажирских поездов |
| `--max-wait N` | порог ожидания для повышения приоритета |
| `--seed N` | начальное значение генератора случайных чисел |
| `--delay-ms N` | длительность модельной минуты в миллисекундах |
| `--until N` | остановка на указанной модельной минуте |
| `--log PATH` | имя файла подробного лога |

Если параметры не указаны, используются значения по умолчанию. Функция
`read_config` читает аргументы и проверяет, что числа находятся в допустимых
границах. Всего можно создать не более 200 поездов.

Значение `--delay-ms 0` означает быстрый режим: одна модельная минута длится
1 мс. Для более наглядного вывода можно указать `--delay-ms 100`.
Параметр `--until 0` означает, что ограничение времени отключено.

## 3. Структура проекта

Программа написана на языке C для Linux с использованием библиотеки pthread
и разделена на несколько небольших файлов.

| Файл | Назначение |
| --- | --- |
| `main.c` | запуск программы, открытие лога и обработка сигналов |
| `config.c` | значения по умолчанию и чтение параметров |
| `simulation.c` | создание поездов, потоки, выбор направления и моделирование |
| `railway.h` | структуры, перечисления и объявления функций |
| `sync.c`, `sync.h` | уведомления через семафоры или условные переменные |
| `tests.c` | тесты основных функций и режимов |
| `run_tests.sh` | запуск тестов |
| `run_examples.sh` | запуск подготовленных примеров |
| `Makefile` | команды сборки |

Основная программа `railway` использует мьютекс и POSIX-семафоры.
Дополнительно реализована программа `railway_cond`, в которой уведомления
работают через условные переменные. Правила движения и параметры обеих
программ одинаковые.

## 4. Основные структуры данных

Структура `Train` хранит номер поезда, направление, тип, время прибытия,
время въезда, время выезда и текущее состояние.

Состояния поезда заданы `TrainState`:

- PLANNED — поезд ещё не прибыл;
- WAITING — поезд прибыл и ждёт разрешения;
- PERMITTED — диспетчер выдал разрешение;
- ON_TRACK — поезд находится на участке;
- FINISHED — поезд закончил движение.

Структура `Config` хранит все настройки запуска. `Direction` задаёт
свободный участок и два направления движения. `RunResult` задаёт причину
завершения программы.

Структура `Railway` хранит общие данные модели: массив поездов, направление,
число поездов на участке, статистику, флаг остановки, мьютекс и уведомления.
Через `TrainArgument` каждому потоку передаются адрес общих данных и индекс
его поезда.

### 4.1. Отображение сущностей в потоки

| Сущность | Представление в программе | Поведение |
| --- | --- | --- |
| поезд | отдельный поток `train_thread` и элемент массива `Train` | прибывает, ждёт разрешения, проходит участок и выезжает |
| диспетчер | отдельный поток `dispatcher_thread` | выбирает направление и выдаёт разрешения |
| станции | направления LEFT и RIGHT и ожидающие поезда | хранят ожидающие поезда каждой стороны |
| однопутный участок | направление и занятость в `Railway` | общий ресурс, доступ к которому защищён мьютексом |
| основной поток | функция `simulate` | создаёт потоки, ожидает их завершения и выводит итог |

При N поездах создаются N потоков поездов и один поток диспетчера.
Вместе с основным потоком во время моделирования получается N + 2 потока.
Станции и участок не выполняют самостоятельных действий, поэтому отдельные
потоки для них не создаются.

Пример сценария взаимодействия:

1. Два поезда прибывают с разных сторон и переходят в состояние WAITING.
2. Каждый сообщает диспетчеру о прибытии.
3. Диспетчер выбирает направление и отправляет выбранному поезду разрешение.
4. Этот поезд переходит в ON_TRACK. Встречный поезд продолжает ждать.
5. Через заданное время поезд освобождает участок и сообщает диспетчеру.
6. Диспетчер может разрешить движение поезду с другой стороны.

## 5. Работа потоков

Функция `simulate` создаёт поезда и запускает потоки. Случайные типы и времена
прибытия выбираются до запуска потоков с помощью `rand`. Параметр seed
позволяет повторить исходные данные на одной системе.

Поток поезда дожидается времени прибытия, встаёт в очередь и уведомляет
диспетчера. Затем он ждёт разрешения. После разрешения поезд въезжает на
участок, сообщает о прохождении и в конце освобождает место.

Диспетчер проверяет общие данные и условия въезда. Если поезд может въехать,
диспетчер переводит его в PERMITTED и будит именно его поток.
Переменная `pending` означает, что разрешение уже выдано, но поезд ещё не
въехал. До фактического въезда другое разрешение не выдаётся.

Время вычисляется по `CLOCK_MONOTONIC`. Общего пошагового цикла для поездов
нет: они выполняются независимо. Во время ожидания разрешения или движения
поезд не удерживает мьютекс, поэтому остальные потоки могут работать.

## 6. Работа диспетчера и синхронизация

Функция `oldest` ищет поезд, который дольше всех ждёт в выбранном направлении.
Если несколько поездов прибыли одновременно, выбирается поезд с меньшим
номером.

При стратегии FIFO диспетчер выбирает самый старый поезд. При стратегии
priority сначала рассматриваются пассажирские поезда. Если ожидание самого
старого поезда достигло `max-wait`, он получает приоритет независимо от типа.

Направление нельзя менять, пока участок занят. Ограничение `max-group`
не позволяет бесконечно продолжать одну группу. Число поездов конечно,
поэтому после обслуживания более ранних поездов остальные также получают
разрешение. Порог ожидания повышает приоритет, но не отменяет правила
безопасности.

Общие данные защищены одним мьютексом. Под ним изменяются состояния поездов,
занятость участка, направление и статистика. Запись событий также выполняется
под мьютексом, поэтому строки разных потоков не перемешиваются.

В основной программе у каждого поезда есть семафор `permits[i]` с начальным
значением 0. Диспетчер отправляет разрешение через `sem_post`, а поезд
ожидает через `sem_timedwait`. Семафор `changed` уведомляет диспетчера
о прибытии, въезде и выезде поездов.

В дополнительной программе вместо семафора используются условная переменная,
мьютекс и счётчик уведомлений. Отправитель увеличивает счётчик и вызывает
`pthread_cond_signal`. Получатель проверяет счётчик в цикле и ждёт через
`pthread_cond_timedwait`. Цикл нужен для повторной проверки условия после
пробуждения. Счётчик сохраняет уведомление, если оно пришло до начала ожидания.

## 7. Проверка правил

Перед въездом поезд проверяет разрешение, направление, свободное место
и интервал после предыдущего въезда. Время фактического въезда сохраняется
в `last_entry`.

После въезда и выезда вызывается `valid_state`. Она проверяет:

- число поездов на участке;
- соответствие вместимости;
- одинаковое направление поездов на участке;
- въезд не раньше прибытия;
- длительность завершённого прохождения;
- соответствие сохранённого количества состоянию массива.

Поезд последовательно проходит состояния от PLANNED до FINISHED.
Повторного въезда и выезда в его функции нет. Дополнительно тесты проверяют
по логу, что каждый поезд получил одно разрешение, въехал и выехал ровно
один раз. Также проверяются интервал и размер группы.

Если правило нарушено, создаётся событие INVARIANT и программа останавливается
с кодом ошибки.

## 8. Пользовательский интерфейс и логирование

Пользователь управляет программой через параметры командной строки.
Команда `./railway --help` выводит справку. При неверном параметре программа
сообщает об ошибке.

В терминал и файл лога выводятся запуск, прибытие, постановка в очередь,
выбор направления, разрешение диспетчера, въезд, прохождение, выезд,
освобождение участка, предупреждения и итоговая статистика.

Пример строки:

```text
time=00002 event=ENTER     train=005 dir=L-R  occupancy=3 | Поезд въехал на участок
```

- `time` — текущая модельная минута;
- `event` — тип события;
- `train` — номер поезда;
- `dir` — направление;
- `occupancy` — число поездов на участке.

Для открытия файла используется `open`, для записи — `dprintf` с файловыми
дескрипторами, для закрытия — `close`. После итоговой строки программа сообщает:

```text
Подробный лог записан в файл: railway.log
```

## 9. Завершение программы

При обычной работе программа заканчивается после прохождения всех поездов.
Параметр `--until` позволяет остановить моделирование на определённой минуте.

Для обработки Ctrl+C и SIGTERM используются сигналы. Обработчик только
устанавливает флаг `stop_requested`. Диспетчер замечает его, устанавливает
общую остановку и будит ожидающие потоки.

Все ожидания имеют тайм-аут 10 мс, чтобы можно было регулярно проверять
остановку. Основной поток ждёт завершения всех созданных потоков через
`pthread_join`. Только после этого записывается итог и удаляются объекты
синхронизации. Принудительная отмена потоков не используется.

При остановке выводится частичная статистика. Поезда, не закончившие путь,
не учитываются как завершённые. Если создание потока завершилось ошибкой,
уже запущенные потоки также получают остановку и ожидаются основным потоком.

## 10. Сборка и запуск

Нужны Linux, компилятор C, make и pthread. Команды выполняются из папки `hw2`.

Сборка программы:

```bash
make
```

Запуск с параметрами по умолчанию:

```bash
./railway
```

Пример простого режима:

```bash
./railway --left 3 --right 3 --arrival-max 0 --travel 3 --capacity 1 --gap 1 --max-group 1 --strategy fifo --delay-ms 20
```

Пример группового режима:

```bash
./railway --left 5 --right 4 --arrival-max 0 --travel 8 --capacity 3 --gap 1 --max-group 3 --strategy priority --delay-ms 20
```

Версия с условными переменными принимает те же параметры:

```bash
./railway_cond --left 5 --right 4 --capacity 3 --delay-ms 100
```

| Исходные данные или действие | Результат |
| --- | --- |
| корректные параметры | все поезда проходят участок, код 0 |
| `--until N` | остановка и частичная статистика, код 2 |
| Ctrl+C или SIGTERM | корректная остановка и частичная статистика, код 4 |
| неверный параметр или ошибка выполнения | код 1 |
| нарушение правила движения | остановка, код 3 |

Подготовленные примеры запускаются командой `make examples`.
Команда `make clean` удаляет исполняемые файлы.

## 12. Ограничения

Модель хранит не более 200 поездов. Длина и скорость отдельно не моделируются.
Безопасный интервал задаётся между моментами въезда. Параметр
`passenger-percent` задаёт вероятность типа каждого поезда, поэтому
фактическая доля может отличаться от указанной.

Порядок событий зависит от планирования потоков. Параметр seed повторяет
исходные данные на одной системе, но не фиксирует порядок выполнения потоков.
Результаты повторных запусков и двух версий могут немного отличаться.

Проверка времени выполняется после пробуждения потока. Поэтому поезд может
выехать немного позже заданного времени, а остановка может произойти позже
указанной минуты. Время прохождения и безопасный интервал не сокращаются.

## 13. Итог

В программе реализовано многопоточное моделирование однопутного участка.
Каждый поезд и диспетчер работают в отдельных потоках. Есть простой и
групповой режимы, две стратегии диспетчера, повышение приоритета долго
ожидающих поездов, логирование, проверка правил и корректное завершение.
Подготовлены версии с семафорами и условными переменными.
Работа обеих программ проверена тестами и запусками в разных режимах.
